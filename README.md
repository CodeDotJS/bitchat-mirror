# bitchat-mirror

Unofficial, self-hosted mirror of [bitchat-android](https://github.com/permissionlesstech/bitchat-android) APKs.

APKs are copied into Cloudflare R2 on a schedule. A static site on Vercel serves the download UI and links straight at R2. There is **no app server, no database, and no serverless functions**. Downloads never touch Vercel’s bandwidth meter.

bitchat is **GPLv3**. Redistributing binaries means corresponding source must stay available — every release in the index carries the upstream tag and commit SHA, and the site links to that commit.

This is an **unofficial** mirror. It is not affiliated with the upstream project.

---

## Architecture

```
GitHub Actions (cron / manual)
        │
        ▼
   sync/ (Python)
        │  stream APKs one at a time
        ▼
 Cloudflare R2          public/releases.json  ──►  git commit
   apk/{tag}/…                                    (triggers Vercel)
   checksums/{tag}.sha256
   index/releases.json
        ▲
        │  browser downloads
 Static site (Vercel) ── fetches /releases.json from its own origin
```

| Piece | Role | Cost target |
|---|---|---|
| GitHub Actions | Cron every 6 hours + `workflow_dispatch` | Free tier |
| Cloudflare R2 | Object storage for APKs (≤ ~9.5 GiB budget) | Free tier (0 egress) |
| Vercel | Static hosting of `public/` | Hobby (non-commercial) |

## Quick start (local)

```bash
git clone <this-repo>
cd bitchat-mirror

# Use a real CPython binary (not a Cursor/IDE shim). pyenv example:
#   /path/to/python3.12 -m venv .venv
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# Confirm you're inside the venv before installing:
which python                       # should end with .../bitchat-mirror/.venv/bin/python
python -m pip install -U pip
python -m pip install -r requirements.txt

cp .env.example .env
# edit .env — see “Configuration” below
```

`requirements.txt` includes runtime deps (`httpx`, `boto3`, `python-dotenv`) and
dev deps (`pytest`, `respx`, `ruff`, `moto`). Always install with
`python -m pip install -r requirements.txt` **after** activating `.venv`, so packages
land in the same interpreter you use to run `python -m sync.main`.

### Cursor / AppImage note

If you run commands inside Cursor’s terminal and see `No module named 'boto3'` even
with `.venv` activated, Cursor’s `APPIMAGE` environment variable is hijacking
Python (packages are installed; the wrong interpreter is running). Use the wrapper:

```bash
./sync.sh --dry-run
./sync.sh --release 1.7.4
./sync.sh
```

Or unset the vars yourself:

```bash
env -u APPIMAGE -u APPDIR -u ARGV0 .venv/bin/python -m sync.main --dry-run
```

A normal external terminal (outside Cursor) is unaffected.

### Dry-run (no uploads)

Plans what would be mirrored against the live GitHub API:

```bash
python -m sync.main --dry-run
```

Write a local `public/releases.json` without touching R2 (useful for frontend preview):

```bash
python -m sync.main --dry-run --write-index
```

### Live sync

Requires complete R2 credentials in `.env`:

```bash
# First time: one release only
python -m sync.main --release 1.7.4

# Full policy-driven sync
python -m sync.main
```

### Preview the site

The frontend is plain static files — no build step:

```bash
cd public
python3 -m http.server 8877
# open http://127.0.0.1:8877/
```

## Configuration

Copy `.env.example` → `.env`. **Never commit `.env`.**

| Variable | Required | Description |
|---|---|---|
| `REPO` | no | Upstream repo (`permissionlesstech/bitchat-android`) |
| `R2_ACCOUNT_ID` | yes (live) | Cloudflare account ID |
| `R2_ACCESS_KEY_ID` | yes (live) | R2 API token access key |
| `R2_SECRET_ACCESS_KEY` | yes (live) | R2 API token secret |
| `R2_BUCKET` | yes (live) | Bucket name (e.g. `bitchat-mirror`) |
| `R2_PUBLIC_BASE` | yes (live) | Public base URL, e.g. `https://pub-….r2.dev` |
| `MIRROR_POLICY` | no | `smart` (default), `all`, or `latest:N` |
| `MAX_BYTES` | no | Hard budget, default `10200547328` (9.5 GiB) |
| `LOG_LEVEL` | no | `INFO` / `DEBUG` / … |
| `GITHUB_TOKEN` | recommended locally | PAT or fine-grained token with public repo read |

### Mirror policy

- **`smart`** — every ABI for releases `≥ 1.6.0`; only `arm64-v8a` + `universal` for older. Pre-1.6.0 Tor-era APKs were ~150 MB; 1.6.0+ is much smaller.
- **`all`** — mirror every APK asset.
- **`latest:N`** — only the N most recent **stable** releases (all their APKs).

Newest releases are processed first so the byte budget is spent on what people actually want. If an upload would exceed `MAX_BYTES`, that asset is skipped, a warning is logged, and a **complete** index is still written (unmirrored rows keep their upstream URLs).

## Cloudflare R2 setup

1. In the [Cloudflare dashboard](https://dash.cloudflare.com/), open **R2**.
2. Create a bucket (e.g. `bitchat-mirror`).
3. Enable **public access** / public development URL on the bucket. Copy the `https://pub-….r2.dev` URL into `R2_PUBLIC_BASE`.
4. **Manage R2 API Tokens → Create API token** with Object Read & Write on that bucket. Save:
   - Access Key ID → `R2_ACCESS_KEY_ID`
   - Secret Access Key → `R2_SECRET_ACCESS_KEY`
5. Account ID (sidebar / R2 overview) → `R2_ACCOUNT_ID`.

R2 endpoint used by the sync job:

`https://{R2_ACCOUNT_ID}.r2.cloudflarestorage.com` (region `auto`).

### Object key layout

```
apk/{tag}/{filename}
checksums/{tag}.sha256
index/releases.json
```

## GitHub Actions setup

### Secrets

Repo → **Settings → Secrets and variables → Actions**. Add:

| Secret | Same as local env |
|---|---|
| `R2_ACCOUNT_ID` | yes |
| `R2_ACCESS_KEY_ID` | yes |
| `R2_SECRET_ACCESS_KEY` | yes |
| `R2_BUCKET` | yes |
| `R2_PUBLIC_BASE` | yes |

`GITHUB_TOKEN` is injected automatically by Actions (do not add it as a secret unless you have a reason to override).

### First run

1. Push this repo to GitHub.
2. Confirm secrets are set.
3. **Actions → Sync bitchat-android releases → Run workflow**.
4. Optional inputs:
   - `release` — e.g. `1.7.4` to upload only that tag first
   - `dry_run` — plan + write local index only (no R2 uploads)

On success the workflow commits `public/releases.json` when it changed (message without `[skip ci]` so Vercel redeploys).

Schedule: every **6 hours** (`0 */6 * * *`), plus manual `workflow_dispatch`.

## Deploy the site to Vercel

1. Import this GitHub repository in [Vercel](https://vercel.com/).
2. Framework preset: **Other** (no build).
3. `vercel.json` already sets `"outputDirectory": "public"`.
4. Deploy. The site will serve `index.html`, `archive.html`, and `/releases.json`.

APK download links point at `R2_PUBLIC_BASE` from the index — not at Vercel.

After the first successful sync commit, Vercel should pick up the updated `releases.json` automatically via git integration.

## CLI reference

```bash
python -m sync.main [options]

  --dry-run          Plan only; do not upload to R2
  --write-index      With --dry-run, still write public/releases.json locally
  --release TAG      Only upload assets for this tag (index still lists all releases)
```

Exit code `1` if one or more asset uploads failed (the run still continues past individual failures and still writes the index).

## Frontend

Static HTML / CSS / ES modules in `public/`. No bundler.

| Page | Purpose |
|---|---|
| `/` | Latest release downloads, sideload + verify guidance, BLE mesh visual |
| `/archive.html` | Every release, filters (ABI / channel / search), sanitized release notes |
| `/why.html` | Sourced brief on Indian internet censorship & why the mirror exists |

The UI fetches `/releases.json` from its own origin (CDN-cached, 10s timeout). Mirrored assets link to R2; unmirrored ones are labeled **Upstream only** and link to GitHub.

A local `research/` dossier (gitignored) can hold the claims ledger and offline source archives used while editing `/why.html`.

## Known caveats

- **Scheduled workflows auto-disable after 60 days** of repository inactivity. Commits made by `GITHUB_TOKEN` do not reliably reset that clock. Push manually now and then, or re-enable the workflow when GitHub emails you.
- **`r2.dev` public URLs are rate-limited** and not meant for heavy production traffic. Fine for personal / small use. For real traffic, attach a custom domain to the R2 bucket (needs a domain on Cloudflare — the one paid piece in an otherwise free stack).
- **R2 may require a payment method on file** even for the free tier. Confirm when you enable R2.
- **Vercel Hobby is non-commercial use only.**
- Anonymous GitHub API access is **60 req/h**. Local sync without `GITHUB_TOKEN` will burn that quickly; set a token. Actions is fine — it has `GITHUB_TOKEN`.
- One bad APK must not fail the whole run: failures are logged and skipped; the index stays complete.
